How a budget
stops being a suggestion.

The problem, in plain language

When an AI agent pays for an API, the operator often writes a rule like “never spend more than twenty dollars.” That sentence lives in a prompt. It has no effect on the chain. The agent can exceed it, or expand its own authority. If two agents share one wallet, each can spend the same remaining balance. If a request times out and the agent retries, it can pay twice.

Evidence: Circle, How AI Agents Hold and Spend Money, 19 Nov 2026 — “A prompt that says ‘stay within budget’ expresses intent, but nothing enforces it.” Full citation on the proof page.

The mechanism

01 · Fund once

The owner transfers tUSD8 into one contract. That is the shared pot. It is not a wallet the agent holds.

02 · Grant a session

The owner binds an agent key to a per-call cap, a total cap, a validity window and an optional payee allowlist. Only the owner can create or change a session.

03 · Spend, atomically

The agent signs an EIP-712 payment with a unique payment ID. The contract checks the signature, caps, window, allowlist and shared balance in one transaction, then transfers the tokens.

04 · Ratchet down

Every payment decrements the single shared pot and cannot increment it. A repeated payment ID is rejected. The owner can revoke a session instantly; the next payment fails closed.

What the judge can verify

Four beats, all visible on-chain: two payments approve, a budget-exhaustion block, a duplicate-ID block, and a revocation block. Every successful step has a transaction hash and explorer link; every block has a named custom error. The proof page lists them, and node scripts/verify.cjs <txHash> reproduces the claim from a fresh clone.

Scope boundaries we state before you ask: this is a testnet build with no mainnet deployment. The off-chain verifier is a convenience caller, not the security boundary — all enforcement happens inside the contract. The explorer's source verifier is broken on Aevum, so source identity is pinned by a public repo and exact commit. No external audit has been performed.

Why not just an escrow contract?

Two other projects were already built in this challenge window around invoice escrow and payment routing. Ratchet is a different shape: the unit of value is a capability lifecycle — grant, spend, revoke — over one shared budget, not an invoice lifecycle. The originality criterion in this hackathon carries the highest weight, so prior art was checked before the design was chosen.
